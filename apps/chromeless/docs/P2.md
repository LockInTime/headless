# P2 contract

P2 adds comparison, reproducible QA evidence, controlled Chromium networking,
and a stdio MCP adapter to the existing local browser protocol.

## Commands

```sh
chromeless --session qa visual compare before.png after.png --output diff.png
chromeless --session qa performance get
chromeless --session qa animations list
chromeless --session qa flow start
chromeless --session qa visit localhost:3000/designers/dashboard
chromeless --session qa click --role button --name Continue
chromeless --session qa flow stop --output designer-flow.json
chromeless --session qa flow run designer-flow.json
chromeless --session qa report create --output pr-report.json
```

`visual compare` accepts only existing private PNG artifacts and produces a
private difference PNG. It does not accept filesystem paths. The result is
intended for visual review, not a misleading single-number similarity score.

`performance get` returns current-document browser timing, resource totals,
and best-effort FCP/LCP/CLS values. Cross-origin privacy limits can reduce the
detail available to a page. `animations list` returns the current document’s
bounded animation set with target metadata and timing state.

Flows record only safe navigation actions: visit, click, key press, scroll,
back, reload, wait, and tour. Typed values, cookies, storage values, files,
and recording controls are never stored in a flow. Flow files are private JSON
artifacts and replay rejects unsupported commands. Recording and replay are
bounded to 200 steps.

`report create` produces a private JSON evidence bundle containing page state,
diagnostics, trace, and artifact references. Sensitive cookie and storage
values are not included.

## Controlled networking

On the Linux Chromium runtime:

```sh
chromeless --session qa network emulate --latency 150 --download-kbps 1200
chromeless --session qa network mock set localhost:3000/api/profile \
  --status 200 --content-type application/json --body '{"plan":"pro"}'
chromeless --session qa network mock clear
```

Network emulation uses Chromium CDP. Mocks match exact normalized HTTP(S) URLs,
have a 64 KiB response-body limit, and add no persistent proxy or listener.
They are cleared explicitly or when the browser session closes.

The Linux host accepts only a qualified non-Snap runtime for this CDP pipe.
Automatic selection prefers an installed bundled runtime and native browser
binaries before PATH wrappers. The Docker P2 flow explicitly selects Debian's
`/usr/lib/chromium/chromium`; it never opens a remote-debugging TCP port.

WebKit does not expose a complete, safe interception API. macOS returns
`UNSUPPORTED_CAPABILITY` for emulation and mocking rather than pretending to
control only part of a page’s network traffic.

Downloads remain denied. This is deliberate: captures are private artifacts,
not arbitrary browser downloads. Existing browser profile state continues to
support normal authenticated pages; diagnostics expose metadata by default and
only expose cookie/storage values when the host is started with
`CHROMELESS_ALLOW_SENSITIVE_DIAGNOSTICS=1`.

## Remote agents and MCP

`chromeless-mcp` is a stdio JSON-RPC MCP adapter over the same local Unix
socket used by the CLI. It creates no TCP listener. Start the local browser
host first, then configure a remote agent to run it through SSH:

```sh
ssh hermes-vm chromeless start
ssh hermes-vm chromeless-mcp
```

The adapter exposes one `chromeless` tool whose `argv` input is the normal CLI
argument list. This keeps a VM agent on the same protocol and permissions as a
local CLI agent instead of opening a browser-control port across devices.

## Limits

The public socket protocol remains capped at 1 MiB. Linux’s internal DevTools
pipe accepts up to 128 MiB only for bounded screenshot data before it is stored
as an artifact; full-page screenshot dimensions remain capped at 64 megapixels.
