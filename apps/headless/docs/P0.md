# P0 contract

P0 covers one agent workflow on macOS and Linux without browser scripts or
screen coordinates.

## Acceptance workflow

1. Start a persistent local Headless host.
2. Create a named session.
3. Visit `http://localhost:<port>/designers/dashboard`.
4. Inspect the page and receive stable element references.
5. Tour the full page for an active recorder.
6. Click a `Continue` button by reference or accessible role and name.
7. Wait for the next page to settle.
8. Tour the next page.
9. Return browser window/surface metadata plus a timestamped action trace.

## Architecture

The `headless` CLI sends versioned JSON lines to a persistent host over a
local Unix socket. Both browser engines use the same command contract:

- macOS: the existing visible WKWebView application.
- Linux: a locally launched, qualified non-Snap Chromium runtime controlled by
  its DevTools protocol over inherited fd 3/4 pipes.

P0 opens no TCP listener or Chromium debugger port. Remote control is deferred
until it has authentication, authorization, and transport security.

## Security boundaries

- Socket access is limited to the current operating-system user.
- Requests and identifiers are size-bounded and validated.
- Only allowlisted commands are decoded.
- Page navigation accepts HTTP and HTTPS only, including before agent control
  is enabled in the visible macOS app.
- No arbitrary JavaScript or shell execution command is exposed.
- Agent action and inspection helpers run in an isolated world that page
  globals cannot replace. The macOS best-effort console/fetch/XHR observer
  necessarily runs in the page world; its bounded output is explicitly marked
  untrusted and its provenance is assigned by the host.
- Page-provided text is data and never interpreted as a protocol command.
- External application URL schemes and local-file navigation are rejected.
- Every command has a finite deadline and a structured failure response.
- Linux refuses root and does not disable Chromium's sandbox.

## Recording contract

`capture.info` returns the macOS window identity or Linux browser PID/target,
page state, and command trace. `tour --full-page` scrolls the page for an OS
recorder, OBS/FFmpeg, CI recorder, or a later built-in recorder.

## Verification

- Shared protocol suite: codec bounds, URL/identifier/parameter allowlists,
  CLI parsing, private socket permissions, live-socket replacement protection.
- macOS E2E: named session, semantic snapshot, isolated-world tamper test,
  bounded hostile-page output, fill/press, external-scheme
  rejection, full-page tours, click/wait, back/reload, and recorder metadata.
- Linux E2E: the same portable flow under sandboxed Chromium plus an assertion
  that the fixture server is the only TCP listener.

## Compatibility

Both browser engines must pass the same conformance suite. Portable command and
error behavior must stay consistent; capture metadata may differ by engine.
