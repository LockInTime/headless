# P2 contract

P2 adds comparison, reproducible QA evidence, controlled Chromium networking,
and a stdio MCP adapter to the existing local browser protocol.

Both platform hosts now run through one `HostCore` command dispatcher in the
shared protocol library. `WebKitBrowserEngine` and `ChromiumBrowserEngine`
adapters contain only engine-specific browser operations; shared session
lifecycle, traces, flows, captures, recordings, reports, artifacts, and error
mapping are implemented once. Unsupported engine features remain explicit
typed capability errors.

`headless capabilities` includes an exhaustive `engines` matrix generated from
the same engine profiles used by `HostCore`; `ping` returns the active profile.
The matrix declares command support and the intentional PDF, element-capture,
JPEG, cookie, recording-navigation, diagnostics, clipboard, and network
differences. Both engines return `OPERATION_FAILED` for `back` without history,
share the 65-second tour bound, and enforce the same key-length contract.

Both platform E2E suites execute `Tests/conformance.sh` against their real
browser. This single scenario checks shared JSON response shapes and verifies
that an engine returns its declared capability error where behavior differs;
the platform suites retain only their deeper engine-specific safety coverage.

## Commands

```sh
headless --session qa visual compare before.png after.png --output diff.png
headless --session qa performance get
headless --session qa animations list
headless --session qa flow start
headless --session qa visit localhost:3000/designers/dashboard
headless --session qa click --role button --name Continue
headless --session qa flow stop --output designer-flow.json
headless --session qa flow run designer-flow.json
headless --session qa report create --output pr-report.json
```

`visual compare` accepts only existing private PNG artifacts and produces a
private difference PNG. It does not accept filesystem paths. The result is
intended for visual review, not a misleading single-number similarity score.

`performance get` returns current-document browser timing, resource totals,
and best-effort FCP/LCP/CLS values. Cross-origin privacy limits can reduce the
detail available to a page. `animations list` returns the current document’s
bounded animation set with target metadata and timing state.

Flows record only safe navigation actions: visit, click, key press, scroll,
back, reload, wait, and tour. Typed values, cookies, storage values, files,
and recording controls are never stored in a flow. Flow files are private JSON
artifacts and replay rejects unsupported commands. Recording and replay are
bounded to 200 steps.

`report create` produces a private JSON evidence bundle containing page state,
diagnostics, trace, and artifact references. Sensitive cookie and storage
values are not included.

All diagnostics are page evidence. Protocol 0.5 marks diagnostic reports,
events, derived issues, console listings, and network listings/details with
`untrustedContent: true`. On macOS, console/fetch/XHR observation must patch
the page world because WKWebView has no isolated-world API for those streams;
the bridge is page-observable and forgeable by design. The host therefore
overrides its source as `webkit-page-bridge`, accepts at most 500 bridge events
per document, and reports truncation. Agent actions and inspection remain in
the separate `HeadlessAgent` content world.

## Controlled networking

On the Linux Chromium runtime:

```sh
headless --session qa network emulate --latency 150 --download-kbps 1200
headless --session qa network mock set localhost:3000/api/profile \
  --status 200 --content-type application/json --body '{"plan":"pro"}'
headless --session qa network mock clear
```

Network emulation uses Chromium CDP. Mocks match exact normalized HTTP(S) URLs,
have a 64 KiB response-body limit, and add no persistent proxy or listener.
They are cleared explicitly or when the browser session closes.

The Linux host accepts only a qualified non-Snap runtime for this CDP pipe.
Automatic selection prefers an installed bundled runtime and native browser
binaries before PATH wrappers. The Docker P2 flow explicitly selects Debian's
`/usr/lib/chromium/chromium`; it never opens a remote-debugging TCP port.

WebKit does not expose a complete, safe interception API. macOS returns
`UNSUPPORTED_CAPABILITY` for emulation and mocking rather than pretending to
control only part of a page’s network traffic.

Downloads remain denied. This is deliberate: captures are private artifacts,
not arbitrary browser downloads. Existing browser profile state continues to
support normal authenticated pages; diagnostics expose metadata by default and
only expose cookie/storage values when the host is started with
`HEADLESS_ALLOW_SENSITIVE_DIAGNOSTICS=1`.

## Remote agents and MCP

`headless-mcp` is a stdio JSON-RPC MCP adapter over the same local Unix
socket used by the CLI. It creates no TCP listener. Start the local browser
host first, then configure a remote agent to run it through SSH:

The single MCP tool mirrors the remote CLI command surface, including `stop`
and `session close`. Its discovery metadata is therefore explicitly
non-read-only, destructive, non-idempotent, and open-world; clients should
confirm mutating calls according to their policy. These annotations are hints,
not a substitute for the host's socket, validation, and navigation boundaries.

```sh
ssh hermes-vm headless start
ssh hermes-vm headless-mcp
```

The adapter exposes one `headless` tool whose `argv` input is the normal CLI
argument list. This keeps a VM agent on the same protocol and permissions as a
local CLI agent instead of opening a browser-control port across devices.

## Limits

The shared agent runtime is packaged as a compiled JavaScript resource and is
installed once per document in a named isolated world on both engines. Page
scripts cannot replace it, and repeated commands do not resend the runtime;
navigation invalidates the cached Chromium execution context before reuse.

The public socket protocol remains capped at 1 MiB. Linux’s internal DevTools
pipe accepts up to 128 MiB only for bounded screenshot data before it is stored
as an artifact; full-page screenshot dimensions remain capped at 64 megapixels.
