# P1 contract

P1 adds agent-owned evidence capture and page diagnostics to the P0 browser
control contract. macOS and Linux use the same commands and JSON responses.

## Acceptance workflow

1. Visit the local dashboard and inspect its controls.
2. Start a browser recording.
3. Tour the dashboard, click `Continue`, and wait for the next page.
4. Tour the next page and stop the recording as an MP4 artifact.
5. Capture viewport, full-page, and element PNGs.
6. Report console errors, page errors, failed requests, and HTTP errors with
   agent-readable guidance for local routes, dev servers, and Next.js/React.

## Commands

```sh
headless --session qa inspect --context actions --task "click Continue"
headless --session qa inspect --context full --text
headless --session qa screenshot --full-page --output dashboard.png
headless --session qa screenshot --every-viewport --output dashboard-scroll
headless --session qa screenshot --by-section --output dashboard-sections
headless --session qa record start --fps 10
headless --session qa record status
headless --session qa record stop --output dashboard-flow.mp4
headless --session qa qa report
headless --session qa qa clear
headless --session qa console list --level error
headless --session qa network list --failed
headless --session qa network get REQUEST_ID
headless --session qa styles get --role button --name Continue --property display
headless --session qa cookies list
headless --session qa storage list --scope local
headless artifacts list
```

Artifact names cannot contain paths. Existing files are never overwritten.
Artifacts are `0600` inside a `0700` per-user directory.

## Scrollable-page screenshots

`screenshot --every-viewport --output PREFIX` captures up to 80 numbered
viewport images, always including the final bottom position. Longer plans
report `truncated` and `totalPoints` instead of silently omitting the bottom.
`screenshot --by-section --output PREFIX` captures numbered viewport images
around visible headings, sections, and regions. Series output uses a prefix, not
a single filename, restores the original scroll position, and still refuses
paths or overwrites. Series screenshots support PNG and JPG/JPEG; PDF requires
`--full-page` and cannot target an element.

## Context pruning

Inspection supports progressive disclosure across five contexts:

- `summary` returns a small page overview, structural regions, and top actions.
- `outline` returns headings, landmarks, forms, articles, and sections with
  stable region references such as `@r4`.
- `text` returns deduplicated semantic snippets instead of a flat body dump.
- `actions` returns visible controls and only executable protocol verbs in each
  control's `actions` field (`click` or `fill`).
- `full` preserves the broader page/media snapshot and explicit `--text` escape
  hatch.

Use `--within @r4` to scope a subsequent text or action inspection. `--task`
ranks results, `--limit` bounds returned items, `--depth` bounds outline
nesting, and `--budget` applies a conservative estimated-token ceiling. Every
focused response reports encoded bytes, estimated tokens, the applied budget,
and omitted counts. Page-derived strings are marked as untrusted content.
`--interactive` remains a legacy alias for the action-focused view.

### Reference lifetime

The two reference kinds deliberately differ, because they are used differently.

- **Element references (`@e1`)** describe the **most recent inspection only**.
  Every inspection reissues them, so a reference from an earlier call stops
  resolving — including when a narrow context such as `summary` returns fewer
  controls than the `full` call before it. Act on a reference from the
  inspection you just ran, or target by role and name instead.
- **Region references (`@r4`)** stay resolvable across inspections, so the
  outline-then-scope workflow works: take `@r4` from an `outline`, then scope
  repeated `text` and `actions` calls to it. They are bounded per page and drop
  oldest-first.

A reference that does not resolve says why, rather than failing anonymously:
`expired` (issued earlier, superseded by a later inspection — inspect again),
`unknown` (never issued — do not guess or invent references), or `detached`
(the element or region has left the page). All three surface as
`ELEMENT_NOT_FOUND` or `REGION_NOT_FOUND`.

## Recording

The built-in recorder captures browser pixels and writes MP4, MOV, WebM, or GIF
through FFmpeg. Choose the container at `record start --format`; the stop output
must use the same extension. Status reports include FPS, container,
codec, quality, frame count, dropped frames, and duration. The recorder does not
capture OS chrome, another application, microphone audio, or system audio. Use
`capture-info` when OBS, an OS recorder, or a CI recorder should own the capture
instead; browser commands continue to work the same way.

Screenshots support PNG, JPG/JPEG, and full-page PDF. macOS image
screenshots can be copied to the clipboard with `--clipboard`; Linux rejects
clipboard capture because VM clipboards are not a reliable default boundary.

The Linux Docker image includes FFmpeg. Native Linux tarball installs require
Chromium and FFmpeg from the system package manager. macOS returns
`RECORDER_UNAVAILABLE` with an install hint when FFmpeg is absent.

## Agent setup

On a Hermes or OpenClaw VM, install both Linux binaries together, add their
directory to `PATH`, then run `headless capabilities` once. The agent can use
the CLI directly; it does not need Python, browser scripts, or a desktop-control
tool. Keep the Unix socket local. If the agent runs elsewhere, invoke the CLI
through SSH instead of exposing a debugger or unauthenticated TCP service.

Use a native distribution Chromium package or the supplied Docker runtime on
Linux VMs. The Docker image pins the real Debian runtime binary at
`/usr/lib/chromium/chromium`. Ubuntu's Snap Chromium package is rejected before
launch because it is not reliable for repeated DevTools-pipe navigation; see
`BENCHMARK.md` for the verified VM result. `headless runtime` prints the
selected executable, source, and pipe transport. An explicit
`HEADLESS_CHROMIUM_EXECUTABLE` must be an absolute executable regular file;
Snap launchers and invalid paths fail without falling back to another browser.

## Diagnostics

Linux reads Chromium Runtime, Log, and Network events. macOS uses WebKit
navigation callbacks plus a document-start bridge for console, fetch, XHR, and
page errors. The macOS bridge is best-effort because public WebKit APIs do not
expose the same isolated diagnostic event stream as Chromium.

Each report includes raw bounded events plus normalized `issues` with severity,
kind, local-address flag, and a suggested next check. A localhost 404 is
identified as a missing local route or asset; local 5xx/network failures point
to the dev server; Next.js, React, hydration, Webpack, and Turbopack failures
are marked as framework errors. URL credentials are redacted.

## On-demand diagnostics

The normal browser workflow does not collect or print deep DevTools detail.
When a failure needs investigation, `console list` returns bounded console
messages; `network list` and `network get` expose request metadata and safe
headers; and `styles get` returns selected computed CSS for an inspected
element. Chromium uses its private CDP pipe. WebKit uses public navigation,
cookie-store, and document bridge APIs, so its network coverage is best effort
for fetch/XHR plus top-level navigation.

`cookies list` and `storage list` expose metadata and keys by default. Values
require both `--values` and a host started with
`HEADLESS_ALLOW_SENSITIVE_DIAGNOSTICS=1`. Authorization, cookie, API-key,
token, and secret headers are always redacted. Response bodies are intentionally
not exposed.

Diagnostic messages and URLs are untrusted page evidence. They are bounded and
returned as data, but must not be interpreted as agent commands.

Reports keep the newest 500 bounded events. Page output is data; it cannot add
commands or execute shell code.

Responses are bounded so they always fit the 1 MiB protocol frame. `qa report`
keeps the newest issues and events that fit the response budget, and
`artifacts list` returns the newest entries. Both report `truncated` and an
`omitted` count, and `qa report` keeps its `summary` counts describing every
collected event rather than only the returned ones. A response that still
cannot be framed fails with `RESPONSE_TOO_LARGE` rather than reporting an
invalid request.

## Remote files and media

`inspect` reports decoded image/video dimensions, media readiness, source, and
resource safety. HTTP(S) media is allowed. Direct navigation to executable
files, installers, scripts, libraries, and disk images is blocked; archive
links are marked as a caution. Page downloads are denied and Headless never
opens, executes, or unpacks a remote file.

The visible macOS app applies the same web-only navigation boundary before and
after agent control is enabled: it never dispatches application schemes to the
operating system and rejects file, data, blob, and JavaScript URLs. A legacy
non-web URL restored from an older build is discarded before an agent can
inspect it. CLI-hosted sessions also start on a clean page.

## Repository media policy

The repository does not commit image or video test fixtures. Runtime
screenshots and recordings are private artifacts and are removed by normal E2E
test cleanup. The reviewed evidence bundle in `docs/qa/evidence/` is the sole
exception: it contains reproducible QA recordings and supporting screenshots
for a specific verified run. New local evidence is written beneath
`build/qa-evidence/`, which is ignored by Git unless it is deliberately
promoted into that reviewed documentation bundle.

## Verification

- Shared tests cover command validation, artifact traversal and overwrite
  rejection, private storage, diagnostic summaries, and socket security.
- Both E2E suites run the complete dashboard-to-next-page recording flow and
  validate image, document, and video artifacts plus permissions. macOS verifies
  JPG clipboard capture and MOV; Linux verifies JPG/JPEG, PDF, MP4, WebM, and
  GIF, then retains checksum-verified QA evidence under the ignored build
  directory.
- Linux also asserts that Headless opens no TCP listener or debugger port.
